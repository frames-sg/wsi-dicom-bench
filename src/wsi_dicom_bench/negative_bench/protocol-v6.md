# WSI-DICOM Negative Bench: October 23, 2026 amendment

This amendment preserves manifest v5, expected-results-lock-v5.json, protocol-v5.md, catalog v5,
core profile v3, and controls-v4 unchanged, so evidence pinned to catalog v5 keeps its meaning. It
adds catalog v6, core profile v4, manifest v6, expected-results-lock-v6.json, controls-v6, and
`rules/wsi-dicom-requirements-2026c-v1.json` for a `wsi-dicom` candidate whose validator adds seven
requirement families: `iod-value-sets` (Defined Context Groups and Templates of PS3.16, with
Baseline and extensible departures reported as advisories), `wsi-image` (VL WSI Image and Frame
Type, Tiles Overlap, Imaged Volume Depth, Position Reference Indicator, optical path resolution,
derivation, pixel spacing, and the regular tiling), `attribute-relations` (constraints between
Attributes in the Data Set and every Item), `series-set` (Frames of Reference, UID roles, Instance
Numbers, Specimen Identifiers, Frame Extraction history, and patient groups across the evaluated
set), `pixel-attributes` (Pixel Padding, Pixel Aspect Ratio, Icon Images, and palette tables),
`codestream` (each encapsulated Frame is one complete codestream of the coding process its
Transfer Syntax identifies and agrees with the Image Pixel Attributes), and `encoding` (the Data Set
as encoded in the file's bytes: element order, VR and reserved bytes, delimiters, Group Lengths,
private blocks, and character sets), each prefixed `intrinsic-wsi-dicom-2026c-`. Catalog v5 maps none
of these checks, and protocol v5 blocks release on any unadjudicated intrinsic failure, so the
candidate cannot be evaluated against v5.

Catalog v6 is catalog v5 plus one rule per new check (32 intrinsic, decoder, and set rules; four
observers). It also moves one requirement between two catalog-v5 rules: the candidate now enforces
"the Per-Frame Functional Groups Sequence has one Item per Frame" (PS3.3 Table C.7.6.16-1) with the
other Sequence Item counts generated from the DocBook tables, so the clause moves from the
`iod-modules` summary and citations to `iod-sequence-items`. Profile v4 is profile v3 plus one row
per new rule (71 rows); its row CP-IOD-FG-002, the Per-Frame Item count, is remapped to
`iod-sequence-items`. Catalog v6 requires the binary to declare rule set `wsi-dicom-general-v3` or
`wsi-dicom-core-profile-2026c-v4`. The workbench defaults to catalog v6; catalogs v4 and v5 and
their manifests remain selectable.

The suite has 14 controls (15 objects), 10 development entries, and 352 evaluation cases. Two
controls are corrected. The lossy JPEG 2000 controls CP05-J2K-LOSSY-4F and CP08-HTJ2K-LOSSY-4F code
their components with the irreversible multiple component transformation but declared YBR_RCT,
which the new `codestream` rule reports; PS3.5 8.2.4 and 8.2.14 require YBR_ICT. controls-v6 holds
the two files with Photometric Interpretation YBR_ICT and a new SOP Instance UID; their Frames,
Study, Series, Frame of Reference, and specimen identities are unchanged, and
`build_core_profile_controls.py --correct-lossy-photometric` derives them from controls-v4. The 17
carried-forward cases built on them are rebased onto the corrected files; their mutations and seeds
are unchanged.

The 149 carried-forward cases keep their v5 mutations, seeds, domains, and expected rules. One
harness correction changes generated bytes: the eight instance-pair handlers inherited from v4 gave
both Instances of a Series Instance Number 1, which only the members of one Concatenation may share
(PS3.3 C.7.6.16.1). The second Instance now takes the next Instance Number. The handlers are shared,
so regenerating v4 or v5 produces the corrected pairs as well; no v4 or v5 expectation depends on the
Instance Number. The patient identity policy of generation now admits a Patient's Name whose every
component is a placeholder word (RESEARCH, PLACEHOLDER, ANONYMOUS, ANON); every previously admitted
value is still admitted.

The new `requirement-statement-evaluation-v1` cohort has 203 deterministic single-defect cases: 40
attribute relation, 13 WSI image, 7 series set, 3 value set, 25 pixel attribute, 38 codestream, and
77 encoding cases. Codestream cases edit the marker segments, fragments, or donor Frames of one
encapsulated Frame; encoding cases write into the encoded bytes the defects that a DICOM writer
would normalize away (`encoding_rewrite`), and use ordinary Attribute edits for the rest. Every
Attribute a case adds around its defect (a Sequence's required members, the Common Instance
Reference listing of a reference, the ICC Profile an Optical Path palette requires) is otherwise
conformant. Each case records the exact attributes or bytes changed, its DICOM 2026c citation, its
expected rules, and `requirement_ids`: the identifiers, in the candidate's `wsi-dicom requirements
--json` (pinned as `rules/wsi-dicom-requirements-2026c-v1.json`), of the normative statements it
breaks. The value set cases name none, because Context Group and Template bindings are table rows
rather than statements.

Expectations were set by running the frozen candidate recorded in the manifest's
`expectation_provenance` and adjudicating each result against the cited DICOM 2026c text. They are
not blinded. A new case expects the targeted rule and, where another catalog rule independently
reports the same defect, that rule as well (25 cases); no new case has an adjudicated cascade.
Framing that only the encoded bytes show (trailing bytes, the encapsulated Pixel Data VR,
Fragment Item lengths, and delimiters) is reported by `encoding` alone; `pixel-structure`
checks the parsed Pixel Data. On a
carried-forward case, a failure of a v6 rule is an expected failing rule when it reports the mutated
Attribute or the inconsistency the case defines, and an adjudicated cascade when it reports an
unchanged Attribute whose requirement the mutation changed; a v5 expected rule whose requirement a
v6 rule now enforces is recorded as superseded, with its replacement. Every decision, with the
observed message, citation, and rationale, is in the case's `requirement_rule_adjudications`: 15
expected failing rules (`codestream` on NB-PX-001 through NB-PX-006, whose offset tables, fragments,
or codestream the case breaks; `wsi-image` on CP-CF-004, CP-CL-006, and IOD-PRS-009; `series-set` on
CP-ID-002 and CP-ID-003; `dimension-order` on IOD-PRS-012; `iod-sequence-items` on NB-PX-001,
IOD-MOD-006, and IOD-MOD-007), 4 adjudicated cascades (`pixel-structure` on NB-CF-005, whose
unchanged Pixel Data no longer has the length one sample per pixel requires; `wsi-image` on CP-CF-002,
CP-CL-002, and CP-CL-003, where the unchanged Specimen Label in Image or Frame Optical Path
Identifier no longer meets the requirement the mutation changed), and 3 superseded `iod-modules`
expectations (NB-PX-001, IOD-MOD-006, IOD-MOD-007). For carried-forward cases,
`expected_unaffected_rules` is recomputed as every intrinsic rule that is neither expected nor an
adjudicated cascade.

The requirement snapshot lists 919 statements, 553 of them checked by an intrinsic rule. The cohort
names 208 of those. The 31 checked statements of the new rules that no case names are listed with
the reason in `requirement_cases.UNCOVERED`. Thirty need a control the suite does not have
(concatenations, LABEL or OVERVIEW images, two optical paths, a LOCALIZER, JPEG-LS, RLE, JPEG XL,
JPEG 2000 Part 2, Encapsulated Uncompressed, large-frame HTJ2K RPCL, or JPIP Referenced Pixel Data).
One, a Value Length that overstates its Value, leaves the file unreadable to the parser, so the
other rules give no verdict and no single-defect case can hold it. The remaining unnamed
statements belong to catalog-v5 rules whose carried-forward cases exercise them without naming
statements. The test suite fails if a named statement is not checked by one of its case's expected
rules, and holds the count of unnamed checked statements to a limit that may only fall.

Scope remains VOLUME, TILED_FULL, one optical path, one focal plane, no extended depth of field,
and no concatenations; LABEL, OVERVIEW, THUMBNAIL, sparse tiling, source fidelity, calibrated
color, DICOMweb behavior, digital signature verification, and compound defects remain outside this
evaluation. Files with an absent or unrecognized Transfer Syntax UID remain excluded.

Acceptance is unchanged from protocol v4. Run with explicit `core-2026c` selection and the required
external validators dciodvfy, dcentvfy, and validate_iods (edition 2026c). Controls must pass every
required validator. Every negative case must fail all expected rules and its declared domain, and any
intrinsic failure that is neither expected nor an adjudicated cascade blocks release. A timeout,
launch error, unavailable required tool, output truncation, unmapped check, or incomplete check set
is an execution error and cannot count as detection. External-validator verdicts are observations,
not expectations. Report observed counts on the authored challenge; they are not clinical
sensitivity, prevalence, certification, or exhaustive normative coverage.
